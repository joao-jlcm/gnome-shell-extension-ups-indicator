# UPS Indicator (GNOME Shell extension)

UPS indicator for the **Ragtech Easy Pro 4162** in the GNOME Shell panel, reading
data straight from the **Supervise** service — no NUT, no
`/sys/class/power_supply`.

*Languages: [Português](README.pt.md) · [Español](README.es.md) · [Index](README.md).*

## Compatibility

Tested **only** with the **Ragtech Easy Pro 1200VA** (model 4162) UPS. Other
models may use a different protocol or log layout — compatibility issues can be
reported as an [issue on GitHub](https://github.com/joao-jlcm/ups-indicator/issues).

## Why not NUT

This UPS uses a proprietary protocol (Microsol/Supervise). Every NUT driver fails
with `short reply` / I/O error on this device. What works is Supervise itself
(v6) — the vendor software that ships with this UPS. It is a **prerequisite**,
installed at `/usr/local/supervise/`; the extension does not install it.

## How it works

`supsrv` writes a binary history log every second:

    /usr/local/supervise/000/loghora.rgt   1 hour  @ 1 s
    /usr/local/supervise/000/logdia.rgt    1 day   @ 24 s
    /usr/local/supervise/000/logmes.rgt    1 month @ 12 min
    /usr/local/supervise/000/logevt.rgt    events (state changes)

These files are `644 root:root` — readable by gnome-shell **without root**, without
setuid and without a helper script. That is why the extension reads the log
instead of talking to the UPS (the `ttyACM0` device requires privileges).

Each record is 72 bytes:

| offset | type | field |
|---|---|---|
| 0 | uint32 LE | timestamp |
| 4 | uint16 LE | constant `0x0255` |
| 6 | uint16 LE | state (10 = on battery, 11 = on AC power, 18 = AC power normal, 24 = no AC power, 26 = low battery) |
| 8 | uint16 LE | `0xFFFF` = no communication with the UPS |
| 10 | uint16 LE | model id (6 = NEP/Toro/Innergie 1200 TI) |
| 12 | float32 LE | input voltage (V) |
| 16 | float32 LE | output voltage (V) |
| 20 | float32 LE | output current (A) |
| 24 | float32 LE | load (%) |
| 28 | float32 LE | output frequency (Hz) |
| 32 | float32 LE | battery voltage (V) |
| 36 | float32 LE | temperature (°C) |
| 40 | float32 LE | battery charge (%) |
| 44 | float32 LE | firmware version (e.g. 1.4) |

**Timestamp gotcha:** Supervise writes the local time *as if it were UTC*, which
leaves the epoch behind the real clock (3 h here, UTC−3). The reader adds the
timezone offset before comparing; without that, a live daemon looks stale.

## Files

    extension.js    panel indicator + menu
    logReader.js    pure parser (no GNOME, no I/O) — testable with Node
    panelValue.js   pure panel-value formatting — testable with Node
    prefs.js        preferences (GTK4/Adw)
    schemas/        gsettings keys
    po/             gettext sources (POT template + translations)
    locale/         compiled translations (generated by `npm run translations`)
    tests/          parser and classification suite

## Translations

English is the source language; all UI strings are gettext msgids. Translations
live in `po/` and are compiled into `locale/`:

    npm run pot           # regenerate po/ups-indicator.pot from the sources
    npm run translations  # compile every po/<lang>.po into locale/<lang>/LC_MESSAGES/

To add a language, create `po/<lang>.po` (from the POT) and add the language code
to `po/LINGUAS`.

## Configuration

    panel-contents          hidden | icon | percent | icon-percent | icon-and-percent
    panel-field             battery | load | vin | vout | temperature (default battery)
    use-colors              colour by state (green/yellow/red/grey)
    low-battery-threshold   % below which it turns red (default 30)
    temperature-threshold   °C at which the indicator turns orange (default 70)
    update-interval         seconds between reads (default 5)
    stale-after             seconds without a write to consider it "no reading" (default 60)

## Installation

    ln -s "$PWD" ~/.local/share/gnome-shell/extensions/ups-indicator@joao-jlcm.github.io
    npm run build          # compile the gsettings schema
    npm run translations   # compile the translations
    gnome-extensions enable ups-indicator@joao-jlcm.github.io

On Wayland, brand-new extensions only load after logout/login.

## Development

    npm test               # parser + classification, includes the real log if present
    npm run preview        # print the menu content from the real log (no shell)
    npm run dev            # nested GNOME Shell window for testing (needs mutter-devkit)
    npm run build          # after editing the schema
    npm run pack           # build the zip for extensions.gnome.org
    journalctl -f -o cat /usr/bin/gnome-shell | grep -i supervise   # runtime logs

## External dependency

Requires the **Supervise v6** software (the `supsrv` daemon) installed at
`/usr/local/supervise/`. Official download (vendor):
[Supervise Personal 6.3, linux64](https://ragtech.com.br/Softwares_download/supervise_personal_6.3_linux64.tar.gz).

If `supsrv` is not running there is no new log: the indicator turns **grey** and
shows the age of the last reading instead of displaying stale data as if it were
current. See [`install-supervise-systemd.sh`] in the dotfiles/config repository —
the service is what keeps the log alive.
