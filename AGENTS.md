# AGENTS.md

GNOME Shell extension showing the **Ragtech Easy Pro 4162** UPS state in the panel.
It reads the binary history log written by the Supervise service (`supsrv`) —
no NUT, no `/sys/class/power_supply`, no root. Requires the **Supervise v6**
software installed at `/usr/local/supervise/` (version in `suplang.cfg`; vendor
download: https://ragtech.com.br/Softwares_download/supervise_personal_6.3_linux64.tar.gz).
Tested **only** with the Ragtech Easy Pro 1200VA; compatibility issues are
reported as GitHub issues.
See `README.md` for the hardware rationale and the log byte format.

## Structure

```
extension.js            panel indicator + menu (GNOME imports)
logReader.js            pure parser/classifier — no GNOME, no I/O, Node-testable
panelValue.js           pure panel-label formatting — Node-testable
prefs.js                preferences UI (GTK4/Adw); runs in a separate process
about.js                standalone GTK app that shows the Adw.AboutDialog (launched by the menu)
metadata.json           manifest: uuid, gettext-domain, settings-schema, url
stylesheet.css          panel/menu styling
package.json            dev scripts only (GNOME Shell ignores this file)
Makefile                `make <target>` wrappers over the npm scripts (`make help`)
schemas/
  org.gnome.shell.extensions.ups-indicator.gschema.xml
  gschemas.compiled     generated by `npm run build` (gitignored)
po/                     gettext sources: POT template, LINGUAS, <lang>.po
locale/                 compiled .mo, generated by `npm run translations` (gitignored)
tests/parse.test.mjs    parser + classification suite (plain Node)
scripts/preview.mjs     terminal preview of the menu from the real log (no shell)
README.md               index with language links — README.en.md, README.pt.md, README.es.md
```

## Commands

| Command | Does |
|---|---|
| `npm test` | parser + classification tests; also parses the real log if present |
| `npm run preview` | print the menu content from the real log (no shell needed) |
| `npm run build` | `glib-compile-schemas schemas` (after editing the schema) |
| `npm run pot` | regenerate `po/ups-indicator.pot` from `extension.js`/`prefs.js` |
| `npm run translations` | compile every `po/<lang>.po` into `locale/<lang>/LC_MESSAGES/` |
| `npm run pack` | build the extensions.gnome.org zip (compiles `po/` into `locale/`) |
| `npm run release` | `pot` + `translations` + `pack` in one go |

`make <target>` mirrors every npm script (`make help` lists them).

## Versioning and releases

- **Semantic versioning, three parts** (`vX.Y.Z`) for tags and releases.
- `metadata.json` keeps **two** version fields: `version` (integer — required by
  GNOME) and `version-name` (semver string, e.g. `1.0.0`). The About dialog
  shows `v<version-name>`.
- Release flow: bump `version` + `version-name` → `make release` (POT +
  translations + zip) → commit → tag and publish with
  `gh release create vX.Y.Z <zip> --title vX.Y.Z --notes-file <file> --target main`.
- The zip is `ups-indicator@joao-jlcm.github.io.shell-extension.zip` (gitignored).

## i18n

- **English is the source language.** UI strings are gettext msgids; translations live in `po/`.
- Domain `ups-indicator` (declared in `metadata.json` `gettext-domain`).
- In `extension.js`/`prefs.js`: `import {gettext as _} from '.../extension.js'` / `'.../prefs.js'`.
  Call `_()` **inside functions**, never at module top level (translations are initialized after import).
- Interpolated strings use `_('...%s...').format(value)`.
- `logReader.js` stays language-neutral: it returns English msgids (`STATE_LABELS`) and a
  `stale` flag; `extension.js` translates them (`stateText()` mirrors `STATE_LABELS`).
- Add a language: create `po/<lang>.po` from the POT, add `<lang>` to `po/LINGUAS`, run `npm run translations`.

## Code style

- **JS file names: lowerCamelCase mirroring the module** (e.g. `logReader.js`), matching
  GNOME Shell's own files (`extensionSystem.js`, `panelMenu.js`). No single formal standard
  mandates this — Google's guide prefers `log-reader.js`, Airbnb ties the name to the export;
  this project follows the GNOME Shell convention.
- 4-space indentation, single quotes, semicolons (GNOME Shell style).
- Classes `PascalCase`; functions/variables `camelCase`; constants `UPPER_SNAKE_CASE`.
- No comments unless they explain a non-obvious *why* (e.g. the timestamp timezone gotcha).

## Development constraints

- **Enabling** an extension the shell already knows is hot (D-Bus `EnableExtension`).
  **Installing** a new one, or changing `extension.js`/`logReader.js`/`stylesheet.css`/
  `metadata.json`/`.mo`, requires a shell restart (logout/login on Wayland). The shell
  imports an extension module once and caches metadata at startup.
- `prefs.js` and the schema do **not** need a restart: preferences run in a separate
  process, loaded on each open (recompile the schema first with `npm run build`).
- To iterate without logging out: `npm run dev` (a nested GNOME Shell window via the
  GNOME 49+ *devkit*; needs the `mutter-devkit` package installed). Relaunch it after
  each code change. The old `gnome-shell --nested` was removed in GNOME 49.
- `gnome-extensions pack` does **not** embed `gschemas.compiled` (the installer compiles it),
  but it also does not pick up `logReader.js` automatically — hence `--extra-source=logReader.js`
  in the `pack` script.
